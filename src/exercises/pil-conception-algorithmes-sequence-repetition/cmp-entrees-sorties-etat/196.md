# Contexte

Lors d'une relecture en binôme, ton camarade signale `3` éléments à corriger sur ta copie.

Pour représenter la préparation du bilan de relecture, le programme ci-dessous reçoit ce nombre, le conserve pendant le traitement, puis affiche le bilan final.

```
event: DÉBUT
move: LIRE le nombre de remarques (3)
move: CONSERVER la valeur (3) dans a_corriger
say: AFFICHER "3 ÉLÉMENTS À CORRIGER"
end: FIN
```

# Consigne

Lis le programme puis classe chaque étiquette dans `Entrée`, `État intermédiaire` ou `Sortie`.

# Catégories

1. Entrée
2. État intermédiaire
3. Sortie

# Étiquettes

1. Le nombre `3` fourni à partir de la relecture.
2. Le nombre de remarques lu au début du programme.
3. La variable `a_corriger` contient `3` pendant l'exécution.
4. Le total `3` est conservé avant l'affichage du bilan.
5. L'affichage `3 ÉLÉMENTS À CORRIGER`.
6. Le bilan visible à la fin du programme.

# Solution

1: 1, 2
2: 3, 4
3: 5, 6

# Feedback essai 1

Suis le nombre `3` dans le programme : il est d'abord reçu, puis conservé pendant l'exécution, puis utilisé dans l'affichage final.

# Feedback essai 2

La ligne `LIRE` correspond à l'entrée. La valeur gardée dans `a_corriger` existe pendant le traitement. Le message affiché à la fin correspond à la sortie.

# Feedback

Le nombre `3` fourni par la relecture et lu par le programme constitue l'entrée. Pendant l'exécution, cette valeur est conservée dans `a_corriger` : c'est l'état intermédiaire. Enfin, le message `3 ÉLÉMENTS À CORRIGER` et le bilan visible à l'écran constituent la sortie.
