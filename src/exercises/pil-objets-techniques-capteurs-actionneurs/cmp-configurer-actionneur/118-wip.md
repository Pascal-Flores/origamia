## Frontiere pedagogique

L'eleve part d'un effet concret demande et choisit le bloc qui commande directement l'actionneur correspondant.

La serie travaille :

- le lien entre une commande et l'effet physique produit par un actionneur ;
- la distinction entre mettre en marche, arreter et seulement preparer un reglage ;
- le choix d'un bloc de commande dans une vraie interface de programmation.

La serie ne travaille pas :

- la lecture d'un capteur ;
- la relation capteur vers actionneur ;
- la recherche d'une valeur numerique dans une consigne ;
- l'ordre de plusieurs instructions ;
- l'explication du comportement d'un programme deja termine ;
- le reperage ou la correction d'une erreur.

Cette frontiere evite notamment l'overlap avec `cmp-parametrer-instructions`, `cmp-ordre-sequence`, `cmp-expliquer-programme` et `cmp-corriger-tests`.

## Forme exacte proposee pour 118-120

- Type : `qcu`.
- Media : `interface`.
- Nombre d'essais : `2`.
- Programme visible : un bloc `Au demarrage` sans instruction connectee.
- Choix visibles dans l'interface : trois blocs Blockly natifs, valides et non connectes.
- Reponses du QCU : trois formulations courtes qui reprennent sans ambiguite les commandes visibles dans l'interface.
- Solution : un seul bloc produit l'effet demande.

Structure de chaque exercice :

1. Le contexte presente un objet et l'effet qu'il doit produire.
2. L'interface montre le programme incomplet et trois blocs candidats.
3. La consigne demande quel bloc placer sous `Au demarrage`.
4. Un distracteur commande l'arret de l'actionneur.
5. Un distracteur modifie un reglage ou commande une action proche sans produire l'effet demande.
6. Le premier feedback aide a distinguer commande, arret et reglage sans nommer la solution.
7. Le feedback final explique pourquoi le bloc correct agit sur l'actionneur.

Le lien Vittascience reste uniquement dans le frontmatter. Aucune section de lien ne sera ajoutee dans le corps de l'exercice.

## Variante pilote - 118.md

### Situation

La classe fabrique une boite a quiz. Quand le programme demarre, le haut-parleur doit jouer un son pour annoncer que la partie peut commencer.

Le haut-parleur est silencieux avant le demarrage. Regler son volume ne suffit donc pas a produire le signal.

### Programme Vittascience

Le projet montrera :

- un bloc `Au demarrage` vide ;
- le bloc natif `microbit_audio_play`, regle sur le son `GIGGLE` ;
- le bloc natif `microbit_audio_stop` ;
- le bloc natif `actuators_music_setVolume`, regle sur `255`.

Ces trois types de blocs ont ete verifies dans le projet d'actionneurs fourni a la racine du depot.

### Consigne proposee

> Quel bloc faut-il placer sous "Au demarrage" pour que le haut-parleur joue le signal de depart ?

### Reponses proposees

1. Le bloc qui joue le son Rire.
2. Le bloc qui arrete tous les sons.
3. Le bloc qui regle le volume a 255.

### Solution

Reponse 1.

### Metadonnees proposees

- Nom : `Quiz sur la bonne note`
- Description : `Pour lancer un quiz, l'eleve choisit dans l'interface le bloc qui fait jouer un son au haut-parleur, parmi une commande de lecture, une commande d'arret et un reglage de volume.`
- Situation : `obj-boite-quiz-signal-sonore-demarrage`

### Feedbacks proposes

Feedback essai 1 :

> Le haut-parleur est silencieux au depart. Cherche la commande qui lui demande de produire un son, et non celle qui l'arrete ou qui prepare seulement son volume.

Feedback final :

> Il faut choisir le bloc qui joue le son Rire. Le bloc d'arret maintiendrait le haut-parleur silencieux et le reglage du volume ne lance aucun son a lui seul.
